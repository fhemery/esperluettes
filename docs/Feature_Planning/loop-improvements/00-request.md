# Loop improvements — request

*Standing collector. WRAP's retro (`wrap-task` §0) appends numbered
suggestions here; run the task when the list is worth a pass. Once wrapped, the
next retro starts a fresh one.*

## What I want

Improvements to the loop protocol (`.agents/loop/`), the step skills, the
agent shims, the docs and the dev scripts, surfaced by finished tasks.

*(the previous 22 suggestions were triaged and applied or dropped)*

1. **BUILD marked an e2e acceptance criterion DONE without running it.**
   *(admin-statistics-quotes, phase 5)* The plan's acceptance said "`pnpm run
   e2e` core admin-statistics spec green". The gate only type-checks e2e, so
   the new Citations step had never run. VERIFY found its hover landing one
   slot off and had to rework `AdminStatisticsPage.hoverSlot` (`1527ed0e`).
   Fix: the build skill says that an acceptance line naming `pnpm run e2e` is
   run before the phase goes `DONE`, or reported as "not run" so the phase
   stays `WIP`.
2. **`<x-shared::tabs>` clips on mobile unless `scrollable`.**
   *(admin-statistics-quotes, VERIFY)* A fourth tab on `/admin/statistics`
   was cut off at 375px and scrolled the page sideways (fix `b0cfa03a`).
   PLAN's visual checklist expected the risk, but no phase said to pass the
   prop. Fix: a line in `app/Domains/Shared/AGENTS.md`: "tab strips with more
   than three tabs, or long labels, pass `scrollable`". Or make it the
   default.
3. **Domain events can ship without `registerEvent()`.**
   *(admin-statistics-quotes, DESIGN)* `Quote.ChapterPassageQuoted` had been
   emitted and stored for months but never registered, so stored copies could
   not be rehydrated, replayed or summarised. `Events/AGENTS.md` already warns
   about this, and it still slipped through. Fix: a gate check (or an Events
   test) that every class implementing `DomainEvent` resolves through
   `EventBus::resolveDomainEventClass(X::name())`.
4. **Worktree e2e ports are undocumented and clash with the annotation rewrite.**
   *(calendar-activity-time-picker, checkpoint 2v)* In a worktree whose e2e
   port is published as 8081, a plain `pnpm run e2e` timed out on the web
   server; it took `E2E_PORT=8080 E2E_BASE_URL=http://localhost:8081` to run.
   With that base URL, `AnnotationOverlay.rewriteAssetHost()` (which reroutes
   `localhost:8081/**` to `:8080`) would reroute the app's own requests. Fix:
   document the worktree port pair in `e2e/README.md`, and derive both the
   rewrite's source and target from `BASE_URL` / `APP_URL` instead of literals.
5. **File-local Pest helpers slip through despite the rule and the plan.**
   *(prevent-chapter-copy, phase 1)* The plan said "no file-local helpers" and
   AGENTS.md forbids them, yet `ChapterCopyGuardTest.php` declares four global
   functions. Nothing caught it, because no names collide yet. Fix: a gate check
   that fails on a top-level `function` in `app/Domains/*/Tests/**/*Test.php`.
6. **The BACKLOG status was not advanced past `WIP:PLAN`.**
   *(prevent-chapter-copy)* BUILD and VERIFY both committed, but the row still
   said `WIP:PLAN` at WRAP, so `/continue-task` would have resumed the wrong
   step. Fix: the build and verify skills update the backlog status in the
   same commit as their artifact.
7. **A notification payload change left the auto-generated catalog stale.**
   *(promotion-requested-user-slug, BUILD)* `user_slug` was added to
   `PromotionRequestedNotification::toData()`, but
   `docs/notification-types.md` (generated by
   `notifications:export-types-doc`) still listed `user_name` only; WRAP
   regenerated it. `wrap-task` §5 only mentions *new* types. Fix: the gate (docs
   step) regenerates the catalog to a temp file and fails on a payload diff, or
   build/wrap skills say "any `toData()` key change → regenerate".
8. **Notification's source-user-must-have-a-profile rule is undocumented.**
   *(promotion-requested-user-slug, BUILD)* The spec and plan assumed a
   requester without a profile still notifies staff with an empty slug.
   `NotificationPublicApi` throws `invalid_source_user` when `sourceUserId` has
   no profile, so that end-to-end case cannot happen; BUILD found it by running
   the test and fell back to a mocked test. Fix: one line in
   `app/Domains/Notification/AGENTS.md` invariants.

9. **Subagents edited files with `sed` despite the no-sed rule.**
   *(news-static-page-sound-upload, phase 4 / VERIFY)* Three times, subagents
   modified file content with `sed`, against CLAUDE.md's Edit/Write-only rule.
   The rule is in CLAUDE.md, which spawned subagents do not reliably weigh.
   Fix: the build/verify skills (or the subagent launch template in
   `.agents/loop/`) restate "never edit with sed/awk/Python/heredocs — use
   Edit/Write" in the prompt they hand to subagents.
10. **Interactive mode ran BUILD to VERIFY inconsistently.**
    *(news-static-page-sound-upload)* The loop was changed mid-task (commit
    `24361386`) so interactive mode chains VERIFY after BUILD and stops before
    WRAP. Already applied; check that `.agents/loop/README.md`, the
    `continue-task` / `next-task` skills and the backlog status wording all say
    the same thing.

11. **The CONTEXT template ships a broken relative link in every new task.**
    *(shared-datetime-input-polish, WRAP gate)* `add-task` copies
    `.agents/loop/templates/CONTEXT.md` into `docs/Feature_Planning/<slug>/`, but
    its link `../references/cross-cutting-checklist.md` only resolves from
    `templates/`; the real file is `.agents/loop/references/`. `pnpm run gate`
    (check-docs) then fails on the freshly filed `story-chapter-publish-at-label`
    folder. Fix: make the template link a path that resolves from the copy
    (`../../../.agents/loop/references/cross-cutting-checklist.md`) or drop the
    link and name the file in backticks.
