## 4. Frontend architecture

No runtime front-end change. Two tooling contracts:

**Dependency.** `@types/node` becomes a direct root dev dependency, constrained
to major 24 (the Node major in `.github/workflows/pr-tests.yml`). Today the
only copy is `@types/node@26.x`, pulled transitively by `happy-dom`/`vitest` and
not hoisted to `node_modules/@types`, which is why `"types": ["node"]` in
`e2e/tsconfig.json` fails with TS2688. The tsconfig itself is correct and stays
as is.

**Gate step.** `scripts/gate.js` gains a step, id `e2e-types`, label
"E2E type-check (tsc)", command `pnpm exec tsc -p e2e` (the tsconfig already
sets `noEmit`). The compiler is the repo's `typescript@7` (`tsc` 7.0.2).

- **Scoping**: runs when the branch's changed files include anything under
  `e2e/`, `playwright.config.*`, `package.json` or `pnpm-lock.yaml`; always
  with `--all`; otherwise reported `SKIP` with a reason, like `js`/`build`.
  The dependency and lockfile are in the trigger list because a type-package
  bump is exactly what can break the check without touching a spec.
- **`--quick`** does not skip it: it is a few seconds, `--quick` only exists to
  drop the slow asset build.
- **`--only=e2e-types`** works through the existing `--only` mechanism.
- Needs neither Sail nor the app running; it runs on the host like `vitest`.
- The header comment's usage block and the `--only` step list are updated; so
  are the two docs that enumerate the gate's steps (`AGENTS.md` "Definition of
  done", `docs/Working_With_Agents.md`, and `.agents/loop/README.md` "Gate").

**Spec fixes.** Whatever errors `tsc` reports once Node types resolve are fixed
at the smallest scope satisfying the compiler (type annotations, narrowing,
non-null handling), never by loosening `e2e/tsconfig.json` (`strict`,
`noUncheckedIndexedAccess` stay on) and never by `@ts-ignore`/`any` unless a
Playwright type genuinely cannot express it — each such case noted in the
phase report.

## 6. Testing strategy

- `scripts/gate.js` has no unit tests today and this change does not justify
  introducing a harness for it. Verification is behavioural:
  1. `pnpm exec tsc -p e2e --noEmit` exits 0.
  2. `pnpm run gate` on this branch runs the `e2e-types` step and passes
     (the branch touches `package.json`, so it is in scope).
  3. Negative check: a deliberately introduced type error in a spec makes
     `pnpm run gate -- --only=e2e-types` fail; reverted afterwards, not
     committed.
  4. `pnpm run gate -- --only=e2e-types` on a clean branch path shows the step
     (sanity of the `--only` id).
- `pnpm run e2e` is not required: no spec's runtime behaviour should change.
  If a spec fix touches more than types (it should not), running that spec
  becomes required.

## 7. Tradeoffs locked

| # | Question | Chosen | Rejected | Why |
|---|----------|--------|----------|-----|
| T1 | How to make `node` types resolve | Direct dev dependency `@types/node` on major 24 | (a) `public-hoist-pattern` for `@types/*` in pnpm config; (b) drop `"node"` from `types` | (a) relies on a transitive version (26) not matching the runtime; (b) specs/config use Node APIs (`process.env`, `path`) and would lose their types |
| T2 | Version line | Major 24, matching CI | Latest (26) | Types should describe the Node that actually runs the specs |
| T3 | Gate integration | New scoped gate step | Separate `pnpm run` script only; husky pre-commit hook | Gate is the definition of done — a script nobody runs is today's situation. Pre-commit would add latency to every commit for a rarely touched folder |
| T4 | Scoping | Run only when `e2e/`, `playwright.config.*`, `package.json`, `pnpm-lock.yaml` changed | Always run | Consistent with the other scoped steps; `--all` still forces it |

## 9. Risks acknowledged

- **Unknown error count.** Nothing has ever type-checked the specs; once TS2688
  is gone, `strict` + `noUncheckedIndexedAccess` may surface many errors. If
  they are numerous or require behavioural rewrites, that contradicts the
  out-of-scope line and BUILD stops for the user rather than loosening the
  tsconfig.
- **Two `@types/node` majors in the lockfile** (24 direct, 26 transitive). Harmless
  — pnpm isolates them — but visible in `pnpm why`.
- **TypeScript 7 (native `tsc`)** is recent; if it misbehaves on the e2e
  project where TS 5.x would not, BUILD reports it rather than downgrading.
