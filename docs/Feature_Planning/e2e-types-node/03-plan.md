## Phase 1 — `@types/node` dev dependency + minimal spec type fix

**Goal.** `pnpm exec tsc -p e2e --noEmit` exits 0 on a clean checkout after
`pnpm install`.

Reads: `02-architecture.md` §4 ("Dependency" and "Spec fixes" paragraphs), §9.

Context: today it fails with `TS2688: Cannot find type definition file for
'node'` — `e2e/tsconfig.json` lists `"types": ["@playwright/test", "node"]`,
but the only `@types/node` in the tree is `26.6.2`, transitive (vite/vitest/
commitlint) and not hoisted to `node_modules/@types`. CI runs Node 24
(`.github/workflows/pr-tests.yml`, `node-version: '24'`). The compiler is the
repo's `typescript@^7.0.2`.

**Deliverables.**
- `package.json` — `devDependencies` gains `"@types/node": "^24.x"` (use
  `pnpm add -D @types/node@^24`; keep the resulting caret range on major 24).
- `pnpm-lock.yaml` — regenerated by that command, not hand-edited.
- `e2e/pages/AdminStatisticsPage.ts` — `hoverSlot()` (around line 187):
  `xs[index]` is `number | undefined` under `noUncheckedIndexedAccess`, giving
  `TS18048: 'x' is possibly 'undefined'`. Fix at the smallest scope that keeps
  runtime behaviour for every case that works today — e.g. compute the
  even-split fallback once and use `xs[index] ?? fallback` in the matching
  branch. No `!`, `any` or `@ts-ignore`.
- Any further error `tsc` reports with the 24.x types — same rule. Do **not**
  touch `e2e/tsconfig.json` (`strict` and `noUncheckedIndexedAccess` stay on).
  If more than a handful of errors appear, or one needs a behavioural rewrite
  of a spec, stop and report (A7 in `DECISIONS.md`).

**Tests.**
- The compiler is the test: `pnpm exec tsc -p e2e` fails with TS2688 before the
  dependency, then with the TS18048 above, then exits 0.
- No new test file; `scripts/`/tooling has no unit-test harness and this does
  not justify one (architecture §6).
- `pnpm run e2e` not required unless a fix changes more than types; if
  `AdminStatisticsPage.ts`'s fix changes a runtime path, run the statistics
  graph spec(s) that call `hoverSlot` (`pnpm run e2e -- statistics`) and note
  the result.

**Acceptance.**
- ✅ `package.json` lists `@types/node` under `devDependencies` on major 24.
- ✅ `node_modules/@types/node/package.json` exists and its `version` starts with `24.`.
- ✅ `pnpm exec tsc -p e2e --noEmit` exits 0.
- ✅ `e2e/tsconfig.json` is unchanged; no `@ts-ignore`, `@ts-expect-error`, `any`
  or non-null `!` added under `e2e/`.
- ✅ `pnpm run gate` green.

## Phase 2 — `e2e-types` gate step + docs listing the gate steps

**Goal.** `pnpm run gate` runs the e2e type-check as a scoped step and fails
when a spec has a type error.

Reads: `02-architecture.md` §4 ("Gate step" paragraph), §6, §7 (T3, T4).

Context: after phase 1, `@types/node@24` is a direct dev dependency and
`pnpm exec tsc -p e2e` exits 0. `e2e/tsconfig.json` already sets
`noEmit: true`.

**Deliverables.**
- `scripts/gate.js`:
  - A trigger regex for the new step, next to `NON_ASSET`, e.g.
    `const E2E_TYPES_FILE = /^(e2e\/|playwright\.config\.[cm]?[jt]s$|package\.json$|pnpm-lock\.yaml$)/;`
    and a `touchesE2eTypes(files)` helper normalising `\` to `/` like
    `touchesAssets`.
  - In `main()`: `const e2eTypesTouched = args.all || touchesE2eTypes(changed);`
  - A new entry in `steps`, placed after `js`:
    `{ id: 'e2e-types', label: 'E2E type-check (tsc)', cmd: 'pnpm', args: ['exec', 'tsc', '-p', 'e2e'], skipReason: e2eTypesTouched ? null : 'no e2e/, Playwright config or dependency change on this branch' }`.
    No `skip: args.quick` — `--quick` keeps it (T3/A6).
  - Header comment: default usage line mentions the e2e type-check; the
    `--only=` list becomes `docs|deptrac|php|js|e2e-types|build`; the scoping
    bullets gain one line saying the e2e type-check runs only when `e2e/`,
    `playwright.config.*`, `package.json` or `pnpm-lock.yaml` changed.
- `AGENTS.md` "Definition of done" — the `pnpm run gate` bullet lists the e2e
  type-check among the steps.
- `docs/Working_With_Agents.md` (around lines 53–60) — the gate usage comment
  and the scoping paragraph mention the step and its trigger.
- `.agents/loop/README.md` "Gate" section (around line 198) — same usage comment.
- `e2e/README.md` — one line under the command block: `pnpm exec tsc -p e2e`
  type-checks the specs and the gate runs it when `e2e/` changes. (Not listed in
  architecture §8; it is where an e2e author looks. Drop it if the reviewer
  disagrees.)

**Tests.** Behavioural, per architecture §6 (no harness for `scripts/gate.js`):
- `pnpm run gate -- --only=e2e-types` → step runs (branch touches
  `package.json`), prints `PASS: E2E type-check (tsc)`.
- Negative check: add a throwaway type error to an `e2e/` spec (e.g.
  `const n: number = 'x';`), run `pnpm run gate -- --only=e2e-types` → exit 1,
  compiler output shown, `FAILED: e2e-types`. Revert; never commit it.
- Skip path: run `node -e` against the regex, or temporarily check with a file
  list without e2e/package files, to confirm the step reports
  `SKIP: E2E type-check (tsc) (...)`. Report how it was checked.
- `pnpm run gate -- --quick` still runs `e2e-types`.

**Acceptance.**
- ✅ `pnpm run gate -- --only=e2e-types` passes on this branch.
- ✅ A deliberate type error in a spec makes that command exit non-zero with the
  `tsc` error printed (checked, then reverted).
- ✅ With no change under `e2e/`, `playwright.config.*`, `package.json` or
  `pnpm-lock.yaml`, and without `--all`, the step is reported `SKIP` with a reason.
- ✅ `--all` and `--quick` both run the step.
- ✅ `AGENTS.md`, `docs/Working_With_Agents.md`, `.agents/loop/README.md` and the
  `scripts/gate.js` header all list the step; none links to
  `docs/Feature_Planning`.
- ✅ `pnpm run gate` green, with `e2e-types` in the `PASSED:` line.
